# 事件与方法入口复用

本轮按“优化前后行为不变”执行，基线为提交 `23ce3f1`。目标是减少重复实现和后续维护分歧，不统一不同入口已有的产品策略，不删除公共 API。

## 逐项结果

| 审查项 | 实施 | 明确保留的行为 |
|---|---|---|
| 固件解包 | `FirmwareUnpackDispatcher` 共用服务分派 | 界面支持 Sparse 级联、MCP 仍拒绝 Sparse；CLI 继续使用处理器直接解包；原有后台调度、取消令牌支持、分区选择及错误文本保持不变 |
| 固件打包 | `RegisteredFirmwareFormats` 共用名称查找和元数据目录执行；MCP 的解析策略移入 `FirmwareFormatResolution` | CLI 默认 EXT4、MCP 默认扩展名推断或 CPIO、界面读取项目设置；精确名称与忽略大小写的调用差异保持不变；MCP 显式支持列表不扩展 |
| 文档通知 | `DocumentNotifications` 集中构造、发布消息 | 同步发送；保留所有公开消息构造重载和类型字段；Dock 切换、加载完成、投屏点击仍分别触发，不去重、不改线程 |
| 工作流 | `WorkflowReconstruction` 共用节点创建、输入转换及端点查找 | UI 使用工厂标题和快照坐标，CLI 使用快照标题；实例 ID 映射大小写规则、首个标题匹配、缺失端口回退差异、告警和退出码保持不变 |
| 刷写／备份 | `PartitionProgressThrottle` 共用算法 | 两服务的状态历史分开，仍按分区名节流，间隔 100 ms，100% 总是发送；保留 IProgress 和 Messenger 的发送顺序 |
| 残留消息／语言通知 | 保留公共兼容入口；记录边界 | 不删除无仓库内消费者的公共消息，不迁移语言消费者以免改变同步事件顺序及外部订阅行为 |
| 打开／保存 | 沿用公共打开入口；保存服务改用五种既有编辑器实现的能力接口；合并等待及关闭确认步骤 | 文本另存为、保存命令 CanExecute/正在执行状态、异常处理、保存门锁、显式打开模式、自动保存及关闭范围保持不变 |
| 文件监听／底层事件 | 共用资源管理器监听器配置 | 两个监听根、原有事件订阅、400 ms 防抖、刷新方式和异常处理保持不变；设备发现与媒体／协议事件不跨层合并 |

## 兼容性取舍

这次不修正审查中发现的既有行为差异。尤其不能把以下改动混入重构：

- 给 MCP 增加 Sparse 解包，或统一三个入口的默认打包格式。
- 将工作流 UI 的标题恢复和缺失端口行为改为 CLI 规则。
- 删除文档加载后的属性刷新或投屏点击消息。
- 将进度历史改为按操作实例隔离；这会改变并发同名分区操作收到的通知。
- 因当前仓库没有消费者而删除公共消息，或将语言两种通知通道强制替换成一种。
- 将周期保存、项目切换和程序关闭合并成无差别的全量保存。

## 验证方式

`EntryPointCompatibilityTests` 只调用重构前就存在的入口，包括实际 CPIO 打包、Sparse 提取／拒绝路径、工作区打开通知次数、画布加载以及工作流 CLI 标题覆盖。该文件也复制到独立的原始提交 checkout 编译运行，以免仅验证重构代码自身。

`SharedEntryPointTests` 检查公共实现的边界：进度节流的时间阈值和完成通知、重复文档通知、五种可保存编辑器、两种连接端点回退策略、输入类型转换与运行时数据保留。

服务层和 CLI 回归同时覆盖已有的节点执行、显式打开模式、项目持久化、文件操作、目录增量刷新、自动保存和 MCP 工具测试。构建与测试顺序执行；因已有测试进程占用默认输出目录，最终验证使用独立输出目录，不停止其他进程。
